    Class RedprintManager

    Manages the lifecycle of live Redprint instances created from BlueprintDefinitions.

    Each dispatched redprint is stored in memory and wired with NATS subscriptions that propagate events through the execution graph until a terminal decision or consumer node fires.

    Example

    const rp = redprintManager.dispatch(myBlueprint);
    redprintManager.pushEvent(rp.id, "priceAbove50k", true);
    const result = redprintManager.get(rp.id);

    dispatch

    • dispatch(blueprint: BlueprintDefinition): Redprint

      Creates a live Redprint from a BlueprintDefinition and immediately begins listening for events.

      All nodes are initialised in "waiting" state. NATS subscriptions are registered for every consumer/hybrid/decision node so that upstream events propagate through the graph automatically. Crypto-monitor producer nodes are also auto-started via BinancePriceMonitor.

      Parameters

      • blueprint: BlueprintDefinition

        The blueprint definition to instantiate.

      Returns Redprint

      The newly created and running Redprint.

    pushEvent

    • pushEvent(redprintId: string, nodeName: string, output: boolean): void

      Externally triggers a node in a running redprint by publishing an event to its NATS subject.

      This is the HTTP entry-point for manually firing producer or switch nodes (e.g. from a REST API call). Downstream subscribers will react as if the node had fired naturally.

      Parameters

      • redprintId: string

        ID of the target redprint.

      • nodeName: string

        Name of the node to fire.

      • output: boolean

        The boolean output value to attach to the node's state and forward to downstream subscribers.

      Returns void

      Throws

      If the redprint does not exist, is not in "running" state, or the named node cannot be found.
